Design Memo: Doctor Reporting Tree and Emergency Queue

A tree suits the doctor structure because a reporting hierarchy is naturally non-linear. Each doctor has one supervisor and may have several reports, which maps directly onto one parent and left and right children. A list would flatten those relationships, while a tree keeps them in the structure itself, so any doctor's subtree represents their whole team. Unlike a binary search tree, this tree is not ordered by name, so insert() has to search for the parent and is told which side to use.

Each traversal fits a different kind of task. Preorder visits a parent before its children, so it is useful for copying a tree or printing an organization chart from the top down. Inorder visits the left subtree, the node, then the right subtree, which makes it the standard way to read a binary search tree in sorted order. Postorder visits children before their parent, so it works well when a parent depends on results from below, such as totaling a department's budget or safely deleting a tree.

A heap helps simulate emergency intake because patients arrive unpredictably and the most urgent one must always be seen next, regardless of arrival order. A sorted list would need to shift elements on every arrival, but a heap only keeps the minimum at the root. Insertion and removal each take O(log n) time, and peeking takes O(1). That efficiency matters in real-time systems, where priorities change constantly as new patients arrive. Reordering only one path through the tree keeps the queue responsive even as it grows.
